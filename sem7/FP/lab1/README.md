# Lab1

"Створити програму на Haskell, використовуючи classes і instances. Як БД використовувати MySQL.
7. Розробити інформаційну систему "Спорт на факультеті". Таблиці БД містять таку інформацію: Інформація про студентів та викладачів (...), які займаються у спортивних секціях, графік роботи секцій, план проведення змагань. Передбачити можливість запровадження та коригування інформації. Кількість таблиць має бути більше 5."

Програма є консольною інформаційною системою. Вона підключається до MySQL
(бібліотека `mysql-simple`) і дозволяє переглядати, шукати, додавати, змінювати
та видаляти записи у 7 таблицях. Спільна поведінка всіх сутностей описана
класом `Entity`, а кожна сутність реалізує його у своєму `instance`.

## Таблиці БД

| Таблиця | Призначення |
|---------|-------------|
| `students` | студенти: `id`, `full_name`, `grp`, `phone` |
| `teachers` | викладачі: `id`, `full_name`, `position`, `phone` |
| `sections` | спортивні секції: `id`, `name`, `coach_id` (→ `teachers`) |
| `student_sections` | студенти в секціях (зв'язок «багато до багатьох») |
| `teacher_sections` | викладачі в секціях (зв'язок «багато до багатьох») |
| `section_schedule` | графік роботи секцій: день, час початку й кінця, місце |
| `competitions` | план змагань: назва, секція, дата, місце |

Секція має одного тренера з таблиці викладачів. Графік і змагання належать
секції. При видаленні секції пов'язані записи видаляються каскадно, а викладача,
який є тренером, видалити не можна (зовнішній ключ).

## Типи та класи

| Тип | Призначення |
|-----|-------------|
| `Student`, `Teacher`, `Section`, `Schedule`, `Competition` | записи (рядки) таблиць |
| `class Entity a` | операції над сутністю |
| `instance Entity ...` | п'ять реалізацій, по одній на кожен запис |

Методи класу `Entity`:

| Метод | Призначення |
|-------|-------------|
| `entityName` | назва набору сутностей для меню |
| `describe` | текстове подання запису |
| `searchE` | пошук за підрядком (порожній рядок повертає всі записи) |
| `fetchE` | отримання запису за `id` |
| `promptE` | введення полів з клавіатури (при зміні Enter лишає старе значення) |
| `insertE`, `updateE`, `deleteE` | додавання, зміна, видалення |
| `hint` | довідка перед введенням (за замовчуванням порожня) |

## Алгоритм

1. **Підключення.** Параметри беруться зі змінних середовища (`DB_HOST`,
   `DB_PORT`, `DB_USER`, `DB_PASS`, `DB_NAME`), а за їх відсутності зі значень
   за замовчуванням. Після підключення виконується `SET NAMES utf8mb4`.
2. **Меню.** Головне меню відкриває універсальне меню `crud`. Воно працює з
   будь-яким типом, що є екземпляром `Entity`, тому код меню один для всіх
   сутностей.
3. **Пошук.** Запити з `LIKE` по кількох полях. Для секцій, графіка та змагань
   використано `JOIN`, щоб показувати назви замість номерів.
4. **Зміна.** Запис читається за `id`, поточні значення показуються в підказці,
   порожній ввід залишає їх без змін.
5. **Зв'язки та звіти.** Окреме меню записує студентів і викладачів у секції та
   показує склад секції. Звіти: найближчі змагання, кількість студентів у кожній
   секції (`LEFT JOIN`, `COUNT`, `GROUP BY`), розклад на день тижня.
6. **Помилки.** Кожна дія обгорнута в `catch`: помилка БД (наприклад, порушення
   зовнішнього ключа) виводиться повідомленням, і програма не завершується.

## Запуск

macOS (GHC 9.6.7 через ghcup):

```bash
brew install mysql pkgconf openssl@3 pcre
brew services start mysql
mysql -uroot < schema.sql
export PATH="$HOME/.ghcup/bin:$PATH"
export PKG_CONFIG_PATH="/opt/homebrew/lib/pkgconfig:$(brew --prefix openssl@3)/lib/pkgconfig"
cabal run lab1 -w ghc-9.6.7
```

Для збірки на Mac потрібен файл `cabal.project.local` з шляхами до бібліотек
Homebrew (`extra-lib-dirs`, `extra-include-dirs` для пакетів `mysql` і
`pcre-light`). Користувач БД за замовчуванням: `sport` / `sport123`.

## Перевірка

Після `schema.sql` у БД є 7 таблиць і тестові дані: 6 студентів, 3 викладачі,
4 секції, 5 записів графіка, 5 змагань. Результати роботи програми:

| Дія | Результат |
|-----|-----------|
| Студенти → Пошук `PM-21` | 2 студенти: Kovalenko Oleksandr, Shevchenko Maria |
| Графік → Пошук `Tuesday` | `Volleyball: Tuesday 18:00-19:30, Gym 1` |
| Учасники секцій → Склад секції `1` | студенти Kovalenko, Shevchenko; викладачі Ivanenko, Petrenko |

- Результати збігаються з даними в `schema.sql`: у секції 1 (Volleyball) записані
  студенти 1 і 2 та викладачі 1 і 2.
- Список викладачів відсортований за ПІБ (Ivanenko перед Petrenko).
- Запити виконуються на реальній MySQL, а не на копії даних у пам'яті.

## Висновки

- Клас `Entity` виносить спільну поведінку (вивід, пошук, додавання, зміну,
  видалення) в один інтерфейс, а `instance` для кожного типу додає лише
  специфічні SQL-запити та поля. Функція `crud` через це працює з усіма
  сутностями без дублювання коду.
- Усі запити параметризовані (`?`), тому ввід користувача не вставляється в
  текст SQL напряму.
- Дати й час читаються з БД як текст (`DATE_FORMAT`, `TIME_FORMAT`), що спрощує
  типи в Haskell, а коректність формату перевіряє сама MySQL.
- Тестові дані англійською, тому пошук за українськими словами нічого не
  знайде. Для українських даних достатньо змінити `INSERT` у `schema.sql`.
