# Lab2

"Використовуючи Haskell (GHC з ключем–threaded), створити багатопотоковий додаток:
3. Вирішити систему лінійних рівнянь паралельним варіантом методу Гаусса."

Програма розв'язує систему лінійних рівнянь `Ax = b` методом Гаусса
з вибором головного елемента. Крок виключення розпаралелено за допомогою
`Control.Parallel.Strategies`.

## Алгоритм

1. **Прямий хід.** На кроці `k` опорним обирається рядок з найбільшим за
   модулем елементом у поточному стовпці. Усі рядки нижче опорного оновлюються
   незалежно один від одного, тому вони обробляються паралельно
   (`parListChunk`, блоки по 8 рядків). Складність: O(n^3).
2. **Зворотний хід.** Послідовний, O(n^2).

## Перевірка

- Тест 3x3 повертає `[2.0, 3.0, -1.0]` (з точністю до округлення, ~1e-16).
- Для n = 1500 нев'язка становить 4.774e-15 і для послідовної, і для
  паралельної версії, тобто обидві дають однаковий розв'язок.

## Продуктивність

Компʼютер: MacBook Air M1, 8 ядер. n = 1500.

Прискорення = T_посл(-N1) / T_парал(-Nk), де T_посл(-N1) = 4.698 с.

| Потоків (`-N`) | Послідовно, с | Паралельно, с | Прискорення | Ефективність |
|----------------|---------------|---------------|-------------|--------------|
| 1              | 4.698         | 4.795         | 0.98        | 98%          |
| 2              | 3.590         | 3.241         | 1.45        | 73%          |
| 4              | 2.926         | 2.389         | 1.97        | 49%          |

Ефективність = прискорення / кількість потоків.

З вимкненим паралельним збирачем сміття (`-N4 -qg`, n = 1500):
послідовно 4.847 с, паралельно 4.400 с (виграш ≈1.10).

Для порівняння, мала система (n = 500): при `-N1` послідовно 0.067 с,
паралельно 0.068 с; при `-N4` послідовно 0.072 с, паралельно 0.063 с.

## Висновки

- Відносно послідовної версії на одному потоці програма на 2 потоках
  працює в 1.45 раза швидше, на 4 потоках в 1.97 раза.
- Значна частина цього виграшу дає паралельний збирач сміття (GC) в GHC, а
  не розпаралелене виключення: послідовна версія теж пришвидшується до
  2.926 с при `-N4`, а з вимкненим паралельним GC (`-qg`) паралельна
  версія швидша за послідовну лише в 1.10 раза (4.400 с проти 4.847 с).
  Чистий внесок `parListChunk` при однаковому `-N`: 1.11 на 2 потоках,
  1.22 на 4.
- Імовірна причина невеликого внеску: на кожному кроці створюються нові
  вектори для всіх рядків, що нижче опорного, тож програма багато
  виділяє пам'ять і значною мірою обмежена збиранням сміття.
  Додатково впливають послідовний зворотний хід і зменшення обсягу роботи 
  на кроці.
- На одному потоці паралельна версія не швидша (0.98): створення «іскор»
  (spark) додає невеликі накладні витрати. На малих `n` паралельність
  майже не дає виграшу (n = 500, `-N4`: 0.063 с проти 0.067 с послідовно
  при `-N1`).
